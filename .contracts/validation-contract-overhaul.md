# Validation Contract — PaperTrench product overhaul

Scope: improve the existing extension and its public entry experience without changing the honest paper-trading model, deleting user state, increasing permissions, adding telemetry, or changing live services. Main owns integration. Existing untracked .worktrees are not part of this work. Baseline checkout: e49637e38b5d6329024e1e5b2233d6b809bbf344; Node v24.16.0; extension and server node --test entrypoints executed without reported failures before edits. Harness soundness must be demonstrated by negative controls before final acceptance. No predecessor handoff is being relied on.

## Assertions — all eight must be accounted for
- VAL-DESIGN-01: Three standalone HTML concepts use real PaperTrench vocabulary and genuinely different information architectures. Main judges served screenshots, then chooses the coherent production direction; prototypes explicitly label illustrative data.
- VAL-DASH-02: The real extension dashboard has a redesigned, responsive training-first overview and navigation. Every existing section remains reachable, active navigation is exposed accessibly, settings and real local balances remain intact. Browser-drive the extension page, empty and populated state, all section destinations, and narrow/desktop widths. No page-level horizontal overflow at 320 or 390 CSS pixels.
- VAL-ENTRY-03: Public entry page gives an immediately understandable paper-only promise, usable download/install path, clear local-data/update safety, and no unsupported numerical or security guarantees. Browser-drive primary paths and mobile navigation; preserve existing supported-site links, product demo and integrations unless an obsolete path is explicitly replaced.
- VAL-TRADE-04: Evidence-backed trading/reliability defects found in the existing code are fixed at their source with tests that drive real production functions and fail on the old behavior. Specific cases and expected assertion counts are appended before implementing those fixes. No guessed quotes, changed fee semantics, or schema migration.
- VAL-SAFE-05: Review the extension/page trust boundary, untrusted rendering, backups and server mutation validation. Fix reachable reproducible defects within independent ownership; document any genuinely gated verification. No credentials exposed, no permission expansion, no public posts or real trades.
- VAL-FLOW-06: Load the actual unpacked extension in an isolated browser profile; observe real storage through the service worker, dashboard rendering, popup mode persistence, settings and wallet preservation. Exercise supported-site overlay if reachable; one honest attempt per gated surface, then use isolated browser scenarios against the real scripts. Browser automation must not use the user's desktop/browser or alter their wallet.
- VAL-PROOF-07: Changed-contract tests and relevant existing suites run after all edits; each new behavioral claim has a deliberate negative control on the real function or surface. Backups live at T:/terp-backup/papertrench-overhaul; byte-identical restoration is checked by SHA-256. Record exact expected/executed counts and failures in evidence artifacts rather than claiming success from exit status alone.
- VAL-REVIEW-08: An independent reviewer checks implementation against this contract. Required existing preflight/schema checks run after integration. User-facing changelog/news accurately describe verified changes and do not claim a public release that has not happened.

Concepts -> VAL-DESIGN-01. Dashboard/wayfinding -> VAL-DASH-02, VAL-FLOW-06. Public onboarding -> VAL-ENTRY-03. Reliability -> VAL-TRADE-04. Trust/safety -> VAL-SAFE-05. Evidence and integration -> VAL-PROOF-07, VAL-REVIEW-08.

Any scope amendments and targeted defect assertions must be recorded here before their source edits. Design concepts are review artifacts, not fake application features. No fabricated trading statistics in the production UI.

## Reliability amendment before source edits
- VAL-TRADE-CACHE: resolving one EVM address on BNB then Ethereum must return each chain's own quote, including pair-address aliases, refresh and batch populated cache. Preserve case-sensitive Solana addresses; canonicalize EVM address case and supported chain aliases consistently. Test real resolver with deterministic fetch fixtures.
- VAL-TRADE-CHAIN: unknown requested chains and wrong-chain singular `pair` payloads must return no token; returned pool aliases must belong to the selected token and requested chain. Test real quote API, not source regex.
- VAL-TRADE-RATE: when Jupiter is unavailable, the existing Dexscreener SOL/USD fallback actually executes and returns its finite positive quote. Remove the duplicate solUsd declaration currently shadowing the implementation; verify concurrent calls share the in-flight operation.
- VAL-STATE-QUEUE: expiry sweeps, recording metadata, review completion and attestation migration must mutate the latest wallet inside the same serialized queue used by commits, bump seq only for actual changes, and preserve concurrent fills. Failed reads/writes must not acknowledge a successful wallet commit. Review completion after a reset must not resurrect the old wallet.
These four targeted contract groups must each have a deterministic negative-control failure against the pre-edit production implementation; exact test and assertion counts will be captured from the completed harness before acceptance.

## Safety and public-demo amendment before source edits
- VAL-SAFE-HTML: hostile imported journal sides render inert text with no attacker-controlled element; null/non-string sides do not crash the journal.
- VAL-SAFE-CSV: formula-like string cells (including whitespace/control-prefix variants) export as spreadsheet text, while genuine numeric negative values and missing values retain their semantics.
- VAL-SAFE-SUBMIT: concurrent authenticated submissions cannot regress chain head/length, change the established bankroll or partially update derived tournament records. Reject stale submissions atomically across the real worker/database boundary, without relying on in-process locks.
- VAL-DEMO-QUOTE: public demo uses a finite positive quote for the requested Solana mint from a matching pool, never an arbitrary first pair; an expired quote cannot create a fill even if its timer was throttled. Refresh/recovery is actionable, in-flight work is bounded and duplicate clicks cannot duplicate a fill. Browser exercise valid, wrong-token, expired and network-failure cases against the actual script.

## Reset integration amendment
- VAL-STATE-REPLACE: dashboard reset, popup reset/restore and overlay quick reset commit their wallet, replay/frame clears and attestation metadata in one storage write, serialized with both attestation and wallet writers. Lock order is attestation then wallet, matching legacy migration. Replacement sequence is derived from the latest stored state. A refused/failed worker replacement must surface failure rather than falling back to a racing raw write. Use a bounded, internally authorized replacement payload; no new permissions or externally callable reset route.
